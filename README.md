# AC-Tester: ESP32-S3 Nano + PZEM-016 + Home Assistant

Готовая конфигурация ESPHome превращает PZEM-016 в сетевой мультитестер Home
Assistant. Она публикует текущие, минимальные и максимальные напряжение, ток и
активную мощность, суммарную энергию, частоту и коэффициент мощности. Минимумы и
максимумы сохраняются во flash и сбрасываются отдельной кнопкой в HA.

## Подключение

Используйте **только RS485-трансивер с логикой 3,3 В**, а не 5-вольтовый MAX485
без согласования уровней. Конфигурация рассчитана на уже распаянный
двухпроводный со стороны ESP модуль с **автоматическим переключением направления
приёма/передачи**. Если на плате установлены обычные MAX3485/MAX485, выводы
`DE` и `/RE` потребуют третьего GPIO: только GPIO5 и GPIO6 для такого варианта
недостаточно.

| ESP32-S3 | RS485 | Назначение |
|---|---|---|
| GPIO5 | TX/DI | передача ESP → PZEM |
| GPIO6 | RX/RO | приём PZEM → ESP |
| — | DE и /RE | управляются модулем автоматически |
| 3V3 | VCC | питание трансивера |
| GND | GND | общая земля низковольтной части |
| — | A/B | A/B PZEM-016 |

GPIO5 и GPIO6 заданы substitutions в начале `esphome/ac-tester.yaml` и совпадают
с уже распаянным модулем DMX/RS485. PZEM по умолчанию имеет Modbus-адрес `1`,
9600 8N1.

### Питание PZEM-016

Измерительная часть PZEM-016 получает рабочее питание **от измеряемой сети
переменного тока** через клеммы `L` и `N` (диапазон измерения модуля 80–260 В
AC). Пока на `L/N` нет сетевого напряжения, измерение работать не будет.

Контакт `5V` на коммуникационной колодке PZEM-016 является вспомогательным
выходом 5 В для маломощной интерфейсной части (например, преобразователя
RS485). В руководстве PZEM-016 для этого выхода указана нагрузочная способность
**100 мА**. Эти 5 В формируются отдельным изолированным выходом внутреннего
импульсного блока питания и предназначены для схемы RS485 и внешних
маломощных цепей.

**Питать ESP32-S3 Nano от выхода `5V` PZEM нельзя.** Лимита 100 мА недостаточно
для ESP32-S3 с Wi-Fi: кратковременные токи контроллера превышают этот предел и
могут вызвать просадку 5 В, циклические перезапуски или перегрузку внутреннего
источника PZEM. Схема из интернета с NodeMCU на `5V` PZEM не отменяет указанное
в руководстве ограничение 100 мА и не подходит для AC-Tester.

Используйте отдельный изолированный AC/DC-блок 5 В не менее 1 А (запас нужен
для пиков Wi-Fi ESP32). От него параллельно подайте питание:

* на разрешённый вход `5V`/`VIN` конкретной платы ESP32-S3 Nano;
* на RS485-трансивер — 3,3 В или 5 В строго в соответствии с его схемой.

Выход `5V` PZEM при таком подключении оставьте неподключённым. Не объединяйте
его с выходом отдельного блока 5 В: два источника нельзя соединять параллельно
без предусмотренной схемой развязки.

Объедините земли только низковольтной интерфейсной стороны: `GND` блока,
ESP32, трансивера и контакт `GND` коммуникационной колодки PZEM. Не соединяйте
их с сетевыми `L` или `N`. Перед подачей питания обязательно проверьте маркировку
и документацию именно своей ревизии PZEM и ESP32: у клонов распиновка может
отличаться. Работы с сетевым напряжением выполняйте только при снятом питании и
в закрытом негорючем корпусе; силовую часть должен подключать квалифицированный
специалист.

## Установка

1. Скопируйте `esphome/ac-tester.yaml` в каталог ESPHome.
2. Создайте рядом `secrets.yaml` по образцу `secrets.example.yaml`. Ключ API
   удобно сгенерировать командой `openssl rand -base64 32`.
3. При необходимости замените `board`. В конфигурации указаны реальные GPIO5 и
   GPIO6, а не номера D-пинов с шелкографии.
4. Проверьте и прошейте: `esphome config esphome/ac-tester.yaml`, затем
   `esphome run esphome/ac-tester.yaml`.
5. Добавьте обнаруженное устройство **AC-Tester** в Home Assistant.

## Энергия за период

PZEM хранит не сбрасывающийся счетчик `Energy Total`. Home Assistant вычисляет
из него расход:

* за скользящие **X часов** — statistics `change` (в примере X = 6);
* за календарные сутки — `utility_meter` с циклом `daily`;
* за календарный месяц — `utility_meter` с циклом `monthly`.

Скопируйте `home-assistant/ac_tester_package.yaml` в
`/config/packages/ac_tester.yaml`. Если packages еще не включены, добавьте в
основной `configuration.yaml`:

```yaml
homeassistant:
  packages: !include_dir_named packages
```

Измените `max_age.hours` на нужное X. После перезапуска HA новые сенсоры можно
добавить на dashboard. Если HA назначил суммарной энергии другой entity ID,
замените оба упоминания `sensor.ac_tester_energy_total` в package.

> Счетчик за X часов начнет показывать полный интервал только после накопления
> истории за X часов. Дневной и месячный счетчики сбрасываются по локальной
> временной зоне Home Assistant в начале календарного периода.
